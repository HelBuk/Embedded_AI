\section{Current state of the object detection models}
    Object detection models localize objects on an input picture or on a set of video frames.
    Localization can be performed by different approaches, the most relative to this work are:
    \begin{itemize}
        \item Axis-aligned bounding  box (AABB): (x, y, w, h), which is cheap to annotate
            and fast to predict.
        \item Oriented/rotated bounding box (OBB): apart from AABB an angle $\theta$ of
            the box is introduced,  which is a bit costlier to label.
        \item Polygon: a list of vertices tracing the object boundary. Provides precise
            geometry, however is time-consuming to label.
        \item Pixel mask ("painted area") - most precise 2D shape, ideal for measurement
            and robotics, heaviest to annotate and train on.
    \end{itemize}

    Choosing the right localization strategy should be guided by the structure of
    the available pretrained weights. Training large detectors from scratch is
    both resource- and time-intensive. For example, Ultralytics estimates that
    training YOLOv5 on COCO (118k images, 300 epochs) on a single
    NVIDIA V100-16GB takes approximately $n/s/m/l/x \approx 1/2/4/6/8$ days,
    respectively \cite{UltralyticsYOLOv5Quickstart}. Collecting and annotating
    a dataset of that scale is even more time-consuming. Consequently,
    it is preferable to start from weights pretrained on a dataset whose
    \emph{labeling granularity} matches the task (e.g., axis-aligned boxes
    vs.\ oriented boxes vs.\ masks). If the required annotation is more
    detailed than the pretraining labels, an additional annotation
    effort is needed for transfer learning. Then, if axis-aligned bounding
    boxes (AABB) are too coarse for small or complex objects, a
    richer localization (e.g., oriented boxes or instance masks) to meet
    accuracy requirements would be a better choice.

    Mentioned earlier COCO dataset \cite{Lin2014COCO} is the common
    detection benchmark. It is big enough, varied, well-annotated and
    permissively licensed. The dataset contains photos of 91 objects
    types with a total of 2.5 million labeled instances in 328k
    images.

COCO’s \cite{Lin2014COCO} official detection annotations are
axis-aligned boxes only (bbox: [x, y, width, height]). There
are no oriented boxes in COCO, so the standard YOLOv8/YOLO11
\cite{Redmon2016YOLO} \textit{detect} checkpoints (trained
on COCO 2017) learn AABB by default:

Other common datasets are:

\begin{itemize}
    \item Objects365 \cite{shao2019objects365} (~600k images, 365 classes):
        broader coverage than COCO;
        popular for pretraining backbones/heads before COCO fine-tuning.
    \item Open Images \cite{kuznetsova2020open} (millions of images; boxes,
        masks, relationships):
        huge scale, but label noise is higher; great for scale, weaker for
        cleanliness.
\end{itemize}

It is also possible to convert OBB annotation to AABB annotation with some
loss of information. In order to do so:

Let $w,h$ be side lengths and $\theta$ the rotation (radians, CCW). The tight
axis-aligned box around the rotated rectangle has
\begin{align}
W_{\text{AABB}} &= \lvert\cos\theta\rvert\, w + \lvert\sin\theta\rvert\, h, \\
H_{\text{AABB}} &= \lvert\sin\theta\rvert\, w + \lvert\cos\theta\rvert\, h .
\end{align}
With the same center $(c_x,c_y)$,
\begin{align}
x_{\min} &= c_x - \frac{W_{\text{AABB}}}{2}, &
x_{\max} &= c_x + \frac{W_{\text{AABB}}}{2}, \\
y_{\min} &= c_y - \frac{H_{\text{AABB}}}{2}, &
y_{\max} &= c_y + \frac{H_{\text{AABB}}}{2}.
\end{align}

If the oriented box is given by four corners $(x_i,y_i)$, the enclosing AABB is
\begin{align}
x_{\min}=\min_i x_i,\quad x_{\max}=\max_i x_i,\qquad
y_{\min}=\min_i y_i,\quad y_{\max}=\max_i y_i .
\end{align}

\textbf{COCO bbox} uses $[x_{\min},\,y_{\min},\,\text{width},\,\text{height}]$, then: \\
\begin{align}
\text{bbox}_{\text{COCO}}
= \bigl[\, x_{\min},\; y_{\min},\; x_{\max}-x_{\min},\; y_{\max}-y_{\min} \,\bigr].
\end{align}

\textbf{YOLO txt} uses normalized $(x_\text{center},y_\text{center},w,h)$, then: \\
Given image size $(W_{\text{img}},H_{\text{img}})$,
\begin{align}
x_\text{center} &= \frac{x_{\min}+x_{\max}}{2\,W_{\text{img}}}, &
y_\text{center} &= \frac{y_{\min}+y_{\max}}{2\,H_{\text{img}}}, \\
w               &= \frac{x_{\max}-x_{\min}}{W_{\text{img}}}, &
h               &= \frac{y_{\max}-y_{\min}}{H_{\text{img}}}.
\end{align}

\textbf{Metrics description}:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Intersection over Union (IoU)}: \\
            For a predicted box \(p\) and ground-truth box \(g\), the IoU formula is: \\
            \[
                \IoU(p,g) = \frac{|p\cap g|}{|p\cup g|}
            \]
            IoU plays role of evaluating an object localization. \\
            It quantifies the overlap between a prediction and ground truth bounding boxes by calculating
            the ratio of the intersection (overlapping area) to the union (total area covered by both boxes).
            IoU is a building block for calculating mAP. \\
            The resulting score is a value between 0 and 1, which quantifies how accurately a model has located an
            object in an image. A score of 1 represents a perfect match, while a score of 0 indicates no
            overlap at all. \\
            The key part of using IoU is to define \textit{"IoU threshold"}. This threshold is a predefined value
            (e.g., 0.5) that determines whether a prediction is correct. If the IoU score for a predicted box is
            above this threshold, it is classified as a \textit{"true positive"}.
            If the score is below, it's a \textit{"false positive"}. \\
            This threshold directly influences other performance metrics like Precision and Recall. \\

    \item \textbf{Precision and Recall}: \\
            Precision defines the proportion of true positives among all positive predictions,
            measuring the ability to avoid misclassification. \\
            \[
                \Precision = \frac{\TP}{\TP+\FP},
            \]

            On the other hand, Recall calculates the proportion of true positives among all actual
            positives, measuring the model's ability to detect all instances of a class. \\
            \[
                \Recall = \frac{\TP}{\TP+\FN},
            \]

    \item \textbf{Average Precision (AP)}: \\
        AP computes the area under the precision-recall curve \cite{Goodfellow2016}, providing a single value that encapsulates
        the model's precision and recall performance. \\
        \[
            \AP_{\tau} = \int_{0}^{1} p(r;\tau)\,dr,
        \]
        In order to build the precision-recall curve, the score (confidence) threshold (t) is used:
        \begin{itemize}[leftmargin=1.5em]
            \item Every detection has a score $s \in [0,1]$.
            \item We sweep t from high $\to$ low (equivalently sort detections by score desc and add them one-by-one).
            \item At each t we keep detections with $s \ge t $ and recompute P/R.
            \item This sweep produces the P–R curve.
            \item AP is the area under this P–R curve;
        \end{itemize}
        \begin{figure}[H]
          \centering
          \includegraphics[width=0.8\linewidth]{pics/pr_concept.pdf}
          \caption{Precision–Recall curve.}
        \end{figure}



    \item \textbf{Mean Average Precision (mAP)}: \\
        Another metric - mAP,  extends the concept of AP by calculating the average AP values
        across multiple object classes. \\
        This is useful in multi-class object detection scenarios to provide
        a comprehensive evaluation of the model's performance.
        \[
            \mAP_{0.50} = \frac{1}{C}\sum_{c=1}^{C}\AP_{c,\,0.50},
        \]
        \[
            \mAP_{[0.50:0.95]} = \frac{1}{C}\sum_{c=1}^{C}\frac{1}{10}
                                 \sum_{k=0}^{9}\AP_{c,\,(0.50+0.05k)}.
        \]
        The parameter \(C\) is the number of classes for which detection and classification
        are performed. \\
        The subscript \(0.5\), as well as the set [0.50:0.95], denotes the IoU threshold: predictions
        with \(\mathrm{IoU}\ge 0.5\) are counted as true positives (TP). \\

\end{itemize}
